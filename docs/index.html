01

Architecture

Shipped

A classifier routes the query, five specialist agents research in parallel with tool access, a synthesis step reconciles them, and an assembler validates provenance and emits one canonical JSON document that every render is derived from.

The assembler (amber) is the integrity gate: it is the only place a field is derived or overlaid, so the value synthesis reasons over and the value the report prints come from one source and cannot drift.

03

Eval harness

Shipped

Ground-truth checks anchor the financial claims to audited filings, and the test suite is written so a test can only pass by encoding the property it checks.

  • SEC EDGAR ground truth. Revenue and net income are checked against the audited 10-K figures pulled from EDGAR, with exact and fuzzy matching to tolerate formatting differences.
  • Regression discipline. Fixes ship with fail-before / pass-after tests that encode the property, not the new output, and use arbitrary fixtures (never the real company's numbers) so a test cannot pass by memorizing an answer.
  • Honest about what it measures. Per-claim confidence is bounded by source tier, not statistically calibrated. The harness gives reliable signal on output quality; it does not claim a calibration it has not measured.

05

Tool-calling

Shipped

Agents call structured tools in parallel and the results are folded back as evidence, with each source assigned a reliability tier before it ever reaches a claim.

# Risk agent, turn 1 — tool calls issued in parallel
courtlistener_case_search(query="Apple Inc.")      → 13,833 dockets
sec_edgar_companyfacts(cik="0000320193")        → FY2025 10-K (audited, primary)
web_search(query="Apple DOJ antitrust 2025")       → 6 results, each tiered
samgov_contract_search(name="Apple Inc.")        → active federal contractor

Tools currently in use: SEC EDGAR (company facts and filings), CourtListener (federal dockets), SAM.gov (federal contracts), and tiered web search and fetch.

06

Failure-mode handling

Shipped

The hardest engineering here was not producing a report; it was making the pipeline fail loudly. Early versions failed silently, a section would simply be missing while the report still looked complete, so the work went into the opposite of features.

  • No silent nulls. A section whose agent ran but produced nothing is recorded as status=failed, never None, and the missing section is surfaced in the report's gaps.
  • Bounded retries inside the budget. A timed-out emit cannot stack a second attempt that the agent budget would cut mid-flight; transient errors get a small bounded retry only while time remains.
  • Missing sections move the number. A missing weighted section contributes zero at its full weight, so a report that lost its risk section can no longer show a confident overall score.
# a Phase-1 emit that exceeds the client timeout no longer vanishes
status = "failed"                 # never None
gaps  += ["risk: section timed out"]  # surfaced in the report
overall = 0.40·financial + 0.40·0 + 0.20·social   # missing section drags it down
07

Source attribution

Shipped

Every claim carries its source, a reliability tier, and a confidence bounded by that tier, plus the upstream claims it was synthesized from, so any line in the report can be traced back to evidence.

{
  "claim_id": "c312809e1f5d",
  "value": "DOJ Sherman Act sec.2 case survived motion to dismiss (Jun 30, 2025)",
  "confidence": "HIGH",
  "source_tier": "primary",
  "sources": ["justice.gov", "natlawreview.com"],
  "synthesized_from": ["risk:reg_07", "research:legal_03"]
}

Source tiers, lightest to strongest: community aggregator reputable primary. A claim's confidence can be no higher than its tier allows, so a HIGH · primary claim is grounded in a filing or court record, while an MED · community claim is flagged as needing verification.

09

Auth & ACL pattern

Companion repo

This pipeline reads only public data, so it has no access-control surface of its own. The pattern for governed data lives in the companion RAG platform, where retrieval is access-control aware.

Tenant isolation

Each tenant's documents are partitioned so one tenant's data never reaches another's retrieval results.

ACL-safe retrieval

A query only retrieves chunks the requesting user is authorized to see; permissions are enforced at retrieval, not after generation.

Companion project: a multi-tenant RAG platform with event-driven ingestion, ACL-safe retrieval, and an integrated eval layer. Integrating that retrieval layer into this pipeline is listed under what production would add.

10

Human-in-the-loop approval

Designed

This pipeline produces a report for a person to act on; it does not take consequential action on its own. The approval pattern below is the production design, stated honestly as design rather than shipped code.

  • The report is the checkpoint. The natural human gate is review of the generated report, where every claim already arrives with its source and a confidence bound for the reviewer to weigh.
  • Gate consequential actions. Any move from "report" to "action" (sending, filing, deciding) would sit behind an explicit human approval step, with the full provenance and confidence surfaced to the approver.
  • Low-confidence and third-party claims escalate. Items below a confidence threshold, or allegations involving named third parties, would route to mandatory review rather than auto-proceeding.
11

Security & governance

Shipped Designed

Some of this is enforced today; some is the posture a regulated deployment would require. Both are stated plainly.

  • Public sources only, secrets in env. The pipeline ingests public data, holds no PII, and reads credentials from the environment, never the repo.
  • Named-entity claims are publishing-grade. An AI-generated false claim about a real company is treated as a real exposure: one such claim was caught and scrubbed from git history before the repo went public, and every report now carries a prominent demonstration-and-not-advice disclaimer.
  • What regulated deployment needs Designed. Procurement and security review, compliance attestation, audit posture, and per-tenant isolation are the operational layer a real customer would expect before production, called out rather than glossed over.
12

What I would change for production

Roadmap

The honest gap between a strong demonstration and a system a regulated customer would deploy. Ordered roughly by how much each one matters.

  • Calibrate confidence, do not just bound it. Measure how often HIGH claims are actually right and tune the mapping, turning a defensible bound into a calibrated probability.
  • Finish the loud-failure pass everywhere. The Phase-1 timeout and silent-null work is done; generalize the bounded-output discipline to every agent so no large entity can produce a sprawling or truncated section.
  • Human-in-the-loop approval gates. Build the approval checkpoints described above for any action with consequences.
  • Integrate ACL-safe retrieval. Bring the companion platform's governed retrieval into the pipeline so it can run against private, permissioned corpora, not just public sources.
  • Expand the eval harness. More ground-truth domains beyond financials, plus adversarial and red-team cases for the claims most likely to be wrong.
  • Cost and deploy controls. Per-run and per-tenant budgets, response caching, rate limits, and quotas, with the cost accounting already in place as the foundation.
